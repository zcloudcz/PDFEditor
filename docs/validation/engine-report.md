# Native engine validation — 2026-10-26

Status: preliminary evidence; P01 is not complete and release is not approved.

## Reproduce

Use Node 24.13.0, `npm ci --ignore-scripts`, then:

```sh
npx vitest run src/tests/editor-corpus.test.js src/tests/editor-edge.test.js --maxWorkers=2
npm run qa:unit
npm run qa:types
```

On this Windows host, the sandbox prevents Vitest from renaming its temporary modules. The same commands outside the sandbox work. This is separate from the repaired Windows WASM file-URL bug.

Fixtures are generated by `src/tests/helpers/editor-corpus.js`. The suite writes input/output PDFs, SHA-256 manifest, per-case duration and selected PNGs under `.superpowers/sdd/2026-10-25-online-pdf-editor/corpus/`. They contain synthetic content only. The generator is AGPL-3.0; embedded Liberation Sans is SIL OFL-1.1.

## Results

42/42 cases pass with the bundled fallback font. The full suite passes 1,033 tests across 58 files. TypeScript checking passes. The upstream production build passed after repairing CRLF frontmatter and the Windows build command; it is not yet a curated product distribution.

Coverage includes five standard-font families at four page rotations, full/subset embedded fonts, Czech diacritics, new glyphs in a subset font, colored text/background, CropBox offsets, columns, text/check/radio/dropdown fields, links, metadata, attachments, images, two/100-page documents, image-only scans, scans with text layers, shared Form XObjects and a longer replacement.

PDF.js independently extracts the exported text and renders before/after pages. Assertions check the replacement, absence of the old text from first-page extraction, preserved unchanged text, page count, annotations and field values. Every pixel outside the fixture's declared edit rectangle must remain identical, including rotated and offset CropBox pages. All remaining pages are independently extracted and rendered in full, including pages 2–100 and the second shared-XObject instance. Whitespace in extraction is normalized because Courier is split into multiple text items. The strengthened corpus passes 42/42 cases in approximately 10 seconds on this host.

## Findings and fixes

- Native Node loading used URL pathname, producing `C:\C:\...` on Windows. Passing the file URL preserves drive letters and escaping.
- A subset font cannot encode newly introduced Czech glyphs on its own. The native provider succeeds when supplied the full Liberation Sans font already bundled in the repository. The application now loads that local font for English/Czech instead of requiring an external font download.
- Cached font promises previously populated only the first destination map. Reopening with another map could report success without installing the font. The shared promise now caches bytes and populates every caller's map; a regression test covers this.

## Remaining gates

- Broader encrypted, signed, Type3 and malformed real-world samples remain required; the synthetic edge coverage below does not close P01.
- The 100-page case contains small synthetic digital pages; it does not establish a 50 MB performance claim.
- The first-page pixel assertion excludes the declared edit rectangle. Unedited objects inside that rectangle and arbitrary complex real-world documents require additional cases.
- This suite does not prove safe redaction, history/revision removal, memory limits, browser responsiveness or OCR quality.
- Font substitution needs a visible notice in the product UI. Using a fallback does not guarantee original typography.
- Browser file selection did not complete during manual testing; no browser edit/export success is claimed.
- Corresponding native source rebuild and complete linked third-party notices remain release gates, documented in `docs/legal/components.csv`.

## Edge-case extension — 2026-10-26

The focused run passes 56 tests: the original 42 edit cases (including metadata author and attachment bytes), three pixel-mask negative controls and 11 native edge tests. This is a focused run, not a new full-suite count. No production engine changes were made for this extension.

`src/tests/helpers/editor-edge-fixtures.js` generates synthetic PDFs using existing pdf-lib, zgapdfsigner and node-forge dependencies. No fixtures or packages were downloaded. The signing certificate is a temporary self-signed test certificate; cryptographic integrity is tested separately from trust. Signature result JSON is written under `.superpowers/sdd/2026-10-25-online-pdf-editor/edge-corpus/`.

| Input / action | Observed native behavior | Evidence / limit |
| --- | --- | --- |
| Empty, non-PDF, header-only, catalog truncated at 50 bytes | Rejected with PDF-open error | Same engine subsequently opens the healthy fixture |
| Complete objects but truncated before cross-reference table and trailer | Rejected with PDF-open error | No claim that arbitrary malformed PDFs can be repaired |
| RC4-128, AES-128, AES-256 | Missing/wrong password rejected; correct user password opens and edits | Independent PDF.js extraction confirms input and changed output |
| Export of each encrypted input | Output is **not encrypted** and opens without a password | Native security metadata also reports no encryption; UI password/export messaging still needs browser verification |
| Real detached CMS signature, ordinary native save | Signature detected on input; rewritten export fails crypto validation | Baseline has verified cryptographic integrity and full coverage, but no trusted issuer |
| Same signed input, `saveSpliced({ incremental: true })` | Original byte prefix is identical; original signature verifies with partial coverage | Updated text is readable; the edited revision is not covered by the original signature |
| Synthetic Type3 glyphs alongside standard text | Unrelated standard-text edit preserves Type3 extraction and pixels | This is preservation evidence, not proof that arbitrary Type3 text can be edited |

The application chooses incremental export for signed documents (`app.js`, `saveFile`) and warns that editing changes signature validity. These tests call core directly and explicitly select the corresponding export option; they do not prove the browser toast or save workflow. The application also runs Type3 protection before opening documents, which this native-only preservation test does not exercise.

One unresolved signature-validation issue was observed: PDFium's incremental output contains another serialized signature dictionary with the original ByteRange. The repository validator reports the original signature as cryptographically verified/partial and also reports an invalid duplicate record because that dictionary's Contents is outside the original gap. The tests assert preserved original bytes, exactly one verified partial result, and no full-coverage result; they do not require this duplicate diagnostic to persist. Browser presentation and revision-aware deduplication need separate investigation.

The negative controls deliberately draw a red rectangle over unchanged content outside the edit bounds in normal, 90-degree rotated and CropBox-offset fixtures. The exact same PDF.js renderer and pixel-mask comparator used by the positive corpus rejects all three altered outputs. This demonstrates that the comparison detects outside-mask damage rather than passing trivially.

## Continuous viewport and blank pages — local preview

The continuous viewport keeps the existing `#page` / `#overlay` DOM in one active page slot. Scrolling does not switch the native active page or commit pending text. Clicking another page activates it in place; a subsequent click selects its editable text. Native page handles are used for lazy previews without `loadPage`, with at most six preview canvases (1600-pixel maximum dimension) and one render per animation frame. All page slots retain their real rotated dimensions; the document is not fully rasterized up front. Existing pointer mapping remains relative to the active canvas bounding rectangle, and zoom retains the top visible page fraction.

Native blank-page append keeps the existing document, forms and annotations. The host supplies dimensions in PDF points. An explicit Czech confirmation explains that earlier native text undo entries are cleared when present; content and committed edits remain. The append itself uses a document snapshot for undo/redo. Unified structural/native history remains a P03 limitation, not a completed feature. Failed native blank-page initialization deletes the new page before returning an error.

Focused tests cover mixed-size 100-page slot layout, bounded preview eviction, editor DOM/input retention, click activation without scroll movement, zoom anchoring, scrolled pointer coordinates, native preview retaining dirty edits and native undo, rotated preview dimensions, append snapshot undo/redo with fields/annotations, dimension validation and native initialization rollback. Browser interaction/performance still requires the parent session's manual check.
